# Ontology (Phase 0)

Formal RDFS/OWL-RL + SHACL for the ALM world model. **Postgres remains SoR.**
This directory is documentation + CI — not a runtime graph database.

Version 1.1 introduces an **explicit bounded core vocabulary**: `domain.ttl`
designates core classes with `alm:coreClass` (the kernel answering the
competency questions and fail-closed invariants) and non-core classes with
`alm:nonCoreClass` (subject specializations, claim subtypes, the AI index, and
secondary taxonomies). `validate_ontology.py` machine-checks the boundary
(core ≤ 24, exact partition of declared classes).

| File | Role |
|---|---|
| `domain.ttl` | Classes and properties; versioned, with explicit core/non-core designation |
| `domain.shacl.ttl` | Closed-world shapes mirroring ACCEPTANCE invariants |
| `competency-questions.md` | Six SPARQL sketches + SQL twins (drift-checked against the kernel contract) |
| `fixtures/valid-instance.ttl` | Minimal valid instance for CI |
| `fixtures/invalid-*.ttl` | Six named negative fixtures, one per fail-closed invariant |
| `validate_ontology.py` | rdflib + owlrl + pyshacl checker; writes `semantic-contract-report.json` |
| `semantic-contract-report.json` | Deterministic machine-readable contract evidence (regenerated by the checker) |

```bash
python docs/implementation/alm-intelligence-v1/ontology/validate_ontology.py
```

The checker also drift-tests the competency SQL twins against the shipped
kernel table names in `docs/architecture-contract.md`; stale or missing names
fail the run. SQL-enforced invariants (immutability, append-only evidence) are
reported as UNKNOWN-in-SHACL limitations with a contract drift assertion.

See also: `docs/decisions/2026-07-30-alm-postgres-kernel.md`.
